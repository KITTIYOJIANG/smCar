# 智能视觉组软件测试规划

日期：2026-06-20

## 1. 当前比赛约束

- 赛题核心是虚实结合推箱子：真实小车在 3.2 m x 2.4 m 场地内运动，虚拟系统根据车顶标识牌定位小车，并在车载屏幕上显示俯视图和第一视角。
- 比赛任务从普通推箱子开始，后续会叠加图片分类推箱子、目标数字识别、随机地图、连续关卡等难度。
- 地图文本是 16 x 12 字符网格，这和当前仓库里的 `sokoban_simulator.py`、`maps/` 测试夹具是一致的。
- 当前官方数据集是 10 类动漫人物图片，共 1571 张，后续用于箱子类别识别。
- 竞赛结果受三条链路共同影响：视觉识别是否把屏幕转成正确地图、规划器是否给出可执行解、底盘是否按命令稳定完成移动/对准/推箱。

## 2. 总体路线

### 阶段 A：软件回归基线

目标：任何算法改动前后，都能一键确认规划、命令格式、串口协议没有退化。

验收：

- `python .\run_all_tests.py` 退出码为 0。
- BFS/A* 地图回归全部无解析错误、无搜索超限、无 replay 失败。
- 命令消费者能拒绝坏 JSON、越界坐标、非法方向、非法推箱距离。
- 串口帧格式和响应解析稳定。

### 阶段 B：地图输入闭环

目标：从上位机或屏幕截图稳定得到 16 x 12 地图。

推荐顺序：

1. 先人工把官方上位机地图文本导入 `maps/`，补齐车起点 `@`，用规划器验证是否可解。
2. 再做离线截图识别：输入一张 Game Window 截图，输出同格式地图文本。
3. 最后接 OpenMV/车载摄像头实时识别，把识别结果送入规划器。

验收：

- 每张测试截图都有一份期望地图文本。
- 地图识别脚本输出与期望文本逐字符对比。
- 识别置信度低时不下发动作，进入重新观测。

### 阶段 C：分类模型闭环

目标：识别箱子图案和目的地数字，把普通箱子 `$/.` 扩展成带类别的 `a-z/A-Z`。

推荐顺序：

1. 下载并固定官方 1571 张数据集版本。
2. 先在 PC 上训练轻量分类器，得到混淆矩阵和每类准确率。
3. 做截图裁剪分类测试，模拟车载屏幕角度、亮度、反光、模糊。
4. 再考虑 OpenMV/RT 平台部署，优先保证推理延迟和稳定性。

验收：

- 每类准确率、整体准确率、最差类准确率都有记录。
- 分类错误能在日志里定位到原始图片、裁剪图、预测类别、置信度。
- 分类置信度不足时可以重看或绕行，不盲推。

### 阶段 D：底盘命令闭环

目标：让 `move_to / align_to_box / push_box` 三类命令从 PC 端稳定跑到 RT1064。

推荐顺序：

1. 空车跑 `move_to` 单格、三格、L 形路径。
2. 静止箱子前做 `align_to_box`，记录位置误差和角度误差。
3. 单格推箱，逐步增加到多格推箱。
4. 跑完整 JSON 计划，失败后重新观测并重规划。

验收：

- 每条命令都有日志：时间、命令编号、结果码、耗时、位姿、备注。
- 不允许上一条命令失败后继续盲目执行下一条。
- 真实车结果和 `replay=PASS` 的仿真结果能对齐。

### 阶段 E：整车比赛流程

目标：按状态机完成发车、识别、规划、执行、验证、更新地图、下一关。

推荐顺序：

1. 单关普通推箱子。
2. 单关分类推箱子。
3. 连续关卡，完成后返回发车区触发下一关。
4. 加入失败恢复：推偏、定位丢失、箱子不存在、目标堵塞。

验收：

- 单关成功率和平均用时有统计。
- 失败原因分类清楚，能对应到视觉、规划、控制、机械。
- 每天保留视频、地图、计划 JSON、底盘日志。

## 3. 今日完成的第一步：测试基线

已新增一键测试入口：

```powershell

```

|---|---|
| BFS 地图回归 | 16 张地图，12 张有解通过 replay，4 张无解，无错误 |

这个基线以后就是改算法前后的最低门槛。任何一次修改后，如果这个命令不通过，先不要上车测。

## 4. 下一步建议

下一步做“地图输入闭环”的最小版本：

1. 扩展规划器，支持官方规则里的“箱子到达目标后同时消失”。
2. 确认 `map3.txt` 中 `*` 的官方语义；如果是炸弹，再补炸弹状态和炸墙规则。
3. 开始做截图到地图的离线识别，把识别输出和 `maps/official/` 的文本地图逐字符对比。
4. 等地图识别稳定后，再训练分类模型，不急着一开始就上模型。
